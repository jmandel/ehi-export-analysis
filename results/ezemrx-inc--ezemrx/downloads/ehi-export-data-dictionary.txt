certification does not represent an endorsement by the U.S. Department of Health and Human Services.

ONC Cures Act Final Rule. As required by the Communications Condition of Certification requirements,

documentation to process EHI after it has been exported from its certifies EHR. ezEMRx EHR (Electronic
Health Record) systems provide means for exporting PHI (Protected Health Information) to allow
healthcare providers to share information efficiently while maintaining the privacy and security of patient
data.

other insight to properly make use of this extensive amount of information. The document assumes the
user has a technical understanding HL7 specifications such as C-CDA standards and formatting around CSV
type files.

Understanding resulting EHI Export Files
The resulting export may contain one patient, or a full collection of patients. The result will be zip file/s.
The zip file includes files containing the patient demographics, clinical records, billing records, scanned
records, and more.
The files upon extraction from the zip will adhere to the following structure:
PID_INTERNALNUMBERING.EXT and/or
PID_INTERNALNUMBERING_TYPE.EXT
•
•
•
•

PID refers to the Patient ID. This will be a unique number.
INTERNALNUMBERING refers to an internal control number for the export. This can be
ignored.
TYPE refers to further describing the content of the file. These can be ClaimData or Echart or
patNotes.
EXT refers to the file extension of the resulting exported data. Extensions are XML
(accompanied by a HTML file) and CSV (comma separated values data).

The files are further categorized as follows:
1. Patient Demographics and Clinical Data – HL7 C-CDA formatted
2. Patient Billing and Claims Data – CSV formatted
3. Adhoc Patient Notes such as documented telephone calls – CSV formatted
4. Scanned Records – HL7 CDA formatted

Format of the resulting EHI Export Files
In order to successfully use or import the exported EHI files, the user must understand the formatting of
the resulting files.

Patient Demographics and Clinical Data
The resulting files follows the specification as set for HL7 C-CDA R2.1 specifications. These files
will always result in a pair following an XML and HTML file extension. It must be noted there will NOT be
a TYPE value in the filename. The format and specifications can be referenced at:
https://www.ncbi.nlm.nih.gov/pmc/articles/PMC1380194/
https://www.hl7.org/implement/standards/product_brief.cfm?product_id=447

Scanned Records
The resulting files follows the specification as set for HL7 C-CDA R2.1 specifications. This file will
follow an XML file extension. It must be noted there will there will be a TYPE value called Echart within
the filename. This file contains all patient scanned and uploaded documents and is coded using Base64
encoding. It must be noted, this file could be large in size depending on the amount of scanned data. The
format and specifications can be referenced at:
https://www.ncbi.nlm.nih.gov/pmc/articles/PMC1380194/
